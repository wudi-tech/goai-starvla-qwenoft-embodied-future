# GenBiVLA：面向 RoboDojo 随机场景泛化的双臂策略设计

## 1. 目标

为 GOAI 2026 General Dual-Arm Collaborative Manipulation Challenge 构建一套可复现、可部署的双臂策略。初赛只评测 RoboDojo Generalization 维度，覆盖 12 个基础任务及对应的 12 个 `_random` 配置。项目首先确保完整评测链路与基础得分，再以轻量 VLA 提升跨任务、跨布局和视觉随机化条件下的泛化能力。

项目同时服务两个目标：完成比赛提交；形成可写入简历的双臂 VLA 训练、评测和部署项目。

## 2. 约束

- 单人参赛，常规投入约 1–2 小时/天，关键安装与调试阶段可增加投入。
- 本地笔记本 RTX 3060 不承担 RoboDojo 主仿真，只用于代码阅读、数据检查、适配器开发和离线调试。
- 正式策略必须通过公网 WSS 端点提供服务，并在审核与评测期间保持协议、动作类型和模型不变。
- 最多提交三次有效结果，因此正式提交不能用于调试。
- 不从零训练大型像素级世界模型，不以单个任务的手工规则作为主方案。

## 3. 方案选择

### 方案 A：ACT/DP 与数据增强

工程风险最低，用于验证数据、动作空间、策略适配器、WebSocket 和 24 个评测配置。它是必须保留的基线和提交兜底。

### 方案 B：轻量 VLA 与泛化增强

从 XPolicyLab 已适配且兼容 RoboDojo 双臂数据的轻量模型中选择主模型。候选模型需通过显存占用、训练脚本完整性、动作类型和多视角输入四项检查。通过多任务训练、视觉增强、短动作块和闭环重规划改善随机配置表现。这是主线方案。

### 方案 C：VLA 与 WAM 候选动作筛选

世界模型仅作为可插拔增强：预测候选动作块的任务进度或失败风险并进行排序。只有在 ACT 和 VLA 已完成端到端评测、且现成 WAM 适配器能够复用 GOAI 数据时才实施。

最终采用“ACT 兜底 + 轻量 VLA 主线 + WAM 可选增强”。

## 4. 系统架构

### 4.1 输入与策略

策略接收：

- 任务语言指令；
- 头部相机和可用的左右腕部相机 RGB 图像；
- 左右机械臂本体状态；
- 当前 episode 和模型内部历史状态。

ACT 基线或轻量 VLA 输出与选定动作类型一致的双臂 action chunk。动作类型不预先凭经验决定，而是根据 GOAI HDF5 数据、候选策略 README 和本地基线结果选择；一旦用于正式提交便保持不变。

### 4.2 泛化增强层

训练时使用与公开评测随机化相符但不依赖隐藏评测数据的增强，包括颜色、亮度、裁剪、背景、轻微相机扰动和物体空间变化。多任务数据统一采样，避免简单任务的数据量压制复杂任务。

执行时只运行 action chunk 的前一小段，然后重新获取图像和状态。策略通过重复观察降低长动作块累积误差，并在动作输出前进行限位、有限幅度平滑和非法值检查。

### 4.3 可选 WAM 层

当主线稳定后，VLA 可产生多个候选动作块；现成 WAM 或轻量结果预测头估计任务进度、碰撞、掉落和双臂冲突风险。系统执行综合分数最高候选的前一小段，然后重新观察。若候选生成或 WAM 性能不稳定，则直接旁路该层，不影响基本提交。

### 4.4 部署层

XPolicyLab 适配器负责观测转换、模型加载、动作字典生成、episode reset 和批处理接口。开发阶段先通过无仿真的 debug 模式检查序列化、形状和动作键，再连接 RoboDojo。

正式服务通过固定公网主机和端口提供 WSS。提交表单中的 `host` 可以是稳定域名，不要求 GPU 实例拥有独立公网 IP。TLS 由公网映射或反向代理终止，内部转发到 XPolicyLab WebSocket 服务。服务包含健康检查、自动重启和持久日志，但不在评测期间自动更新模型。

训练/仿真端与公网入口解耦：RoboDojo 环境、GOAI Assets 和 HDF5 数据只供本地仿真与训练；正式 Policy Server 原则上只需要策略代码、checkpoint、配置、tokenizer/预训练权重和必要推理依赖。因此，后续即使更换公网服务器，也不应默认重新下载全部仿真资源。

## 5. 云端资源设计

采用“仿真训练机 + 可选公网入口”的解耦设计，避免为了公网 IP 过早迁移整套环境，也避免长期占用昂贵 GPU：

1. 开发评测机按小时租用，运行 Isaac Sim、RoboDojo、数据处理和本地策略评测。当前使用 AutoDL RTX 5090 32 GB、90 GB 内存、30 GB 系统盘和 550 GB 数据盘，足以承担当前安装、仿真和轻量策略训练。
2. 正式策略端点需要稳定公网 `host:port`、TLS 和持续在线能力，但公网入口与 GPU 可以不在同一台机器上。显存依据最终模型实测选择；ACT/TinyVLA 类模型优先 24 GB，超出后升级至 48 GB。

### 5.1 当前 AutoDL 存储布局

- `/root/autodl-tmp/GOAI/RoboDojo`：RoboDojo 代码及 XPolicyLab、IsaacLab、cuRobo 子模块。
- `/root/autodl-tmp/conda/envs/RoboDojo`：RoboDojo/Isaac Sim 运行环境。
- `/root/autodl-tmp/conda/envs/goai-download`：Hugging Face/Git LFS 下载环境。
- `/root/autodl-tmp/GOAI/GOAI-2026-fast`：GOAI-2026 资源仓库；Assets LFS 总量约 32.65 GiB。
- `/root/autodl-tmp/GOAI/storage_env.sh`：将 Conda、pip、Hugging Face 和缓存路径定向数据盘。

大文件和环境继续放在 `/root/autodl-tmp`，避免 30 GB 系统盘被占满。同一实例关机再开机时数据盘保留，但 `screen` 和下载进程会终止；重新执行 `git lfs pull` 时已完整下载的 LFS 对象会被跳过。

### 5.2 正式公网接入的三级决策

**第一选择：AutoDL 自定义服务直接提交。**

让 Policy Server 监听 `0.0.0.0:6006` 或平台允许的映射端口，通过 AutoDL “自定义服务”获得公网域名和端口。必须从 AutoDL 之外的网络实测 `wss://host:port`，确认 TLS 证书、WebSocket Upgrade、连续推理、重连和端点稳定性。若全部通过，当前 AutoDL 可同时承担正式策略推理，无需迁移或重下资源。评测期间必须保持实例开机。

**第二选择：便宜公网 CPU 网关 + AutoDL GPU。**

当 AutoDL 自定义服务无法稳定提供 WSS 时，租用带固定公网 IP 的轻量 CPU 服务器，参考配置为 2 vCPU、4 GB 内存、40 GB 系统盘和 5–10 Mbps 带宽。网关只负责域名、TLS、WSS 和反向代理，模型仍在 AutoDL GPU 上推理。必须在符合 AutoDL 平台规则的前提下选择连接方式，并实测网关引入的延迟和断线恢复。

**第三选择：迁移最终策略到公网 GPU 服务器。**

只有前两种方案无法满足稳定性或延迟时才迁移。默认只复制策略代码、checkpoint、预处理配置、tokenizer/基础权重和推理依赖，不复制 RoboDojo Assets 或 HDF5 数据。新服务器的 GPU 显存以最终模型单请求推理实测为准。

### 5.3 换机、迁移与备份规则

- 同一 AutoDL 实例关机再开机：不重新下载，只需重新启动进程。
- 更换为 AutoDL 新实例：优先“克隆实例并同时复制数据盘”或使用跨实例数据盘拷贝；只保存系统镜像不能替代数据盘备份。
- 迁移到其他云厂商：优先用 `rsync --partial --append-verify`、OSS/对象存储或 AutoDL 公网网盘传输，不从 Hugging Face 从头下载。
- 只迁移正式 Policy Server：仅传输代码、模型和推理配置；仿真 Assets 继续留在开发机。
- 备份优先级：自研代码、最终 checkpoint、配置、数据统计和实验记录必须备份；可重新获取的公开 Assets 优先级较低。
- 在新服务器完成文件数量/校验、模型加载、GPU 推理和外网 WSS 验证之前，不释放旧实例。

### 5.4 正式提交前的端点冻结门槛

在填写 GOAI 提交表单前，公网策略服务必须同时满足：

- 从不同网络环境连接 `wss://host:port` 成功；
- TLS 证书与域名匹配，不使用自签名证书；
- WebSocket 握手、观测序列化、动作返回、episode reset 和连续多请求全部通过；
- 端到端延迟和推理时间不会导致评测超时；
- 断线、进程异常和实例重启后有明确恢复方法；
- 已冻结策略名称、checkpoint、action type、端点和协议行为，评测期间不再变更。

## 6. 评测与错误处理

在任何正式提交前完成：

- XPolicyLab debug 模式闭环检查；
- 12 个标准配置和 12 个 `_random` 配置的完整 smoke test；
- 每个任务的成功、部分得分、零分、超时、碰撞和通信失败记录；
- ACT 与 VLA 在相同 action type、seed 和评测设置下的对比；
- WSS 跨公网连接、TLS、重连、episode reset 和服务重启测试。

策略遇到 NaN、动作维度错误、超限动作或推理超时时，返回安全的保持/停止动作并记录原因。episode 切换必须清空模型历史状态。网络断开由服务层记录并重启连接，不切换 checkpoint。

## 7. 成功标准

- 正确安装 GOAI 专用资源和数据，24 个配置均能完成端到端运行。
- ACT 基线可复现并形成每任务得分矩阵。
- 轻量 VLA 在 `_random` 配置平均表现上优于 ACT 基线，或在相同得分下显著提升任务覆盖率和稳定性。
- 正式 WSS 端点可由公网访问并在评测窗口持续在线。
- 代码、配置、checkpoint 获取方式、实验记录和复现命令完整可交付。

## 8. 非目标

- 不从零训练大型视频生成世界模型。
- 不在未确认规则允许时使用按任务切换 checkpoint 的隐藏路由。
- 不为追求关键词牺牲 24 个配置的可运行性。
- 不在正式评测期间自动修改模型、动作类型或协议行为。
